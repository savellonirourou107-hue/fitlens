## 2. 高严重 Bug（Phase 3 候选）

按 spec：仅修 `severity=High` 且 `category ∈ {bug, boundary, error-handling}` 的发现。性能项一律不动代码。

### BUG-003 · minimax.js parseModelJson 隐藏 AI 解析失败

- **文件**：`backend/src/services/minimax.js:64-74`
- **原严重度**：High · 复核后：High · **confidence**：high
- **类别**：bug
- **证据**：正则 `/\{[\s\S]*\}/` 贪心匹配第一个 `{` 到最后一个 `}`。对 "ignore {a:1} ... {b:2}" 类输出会得到畸形字符串 → JSON.parse 失败 → catch 静默吞掉 → 兜底返回 `{items: []}`，与 JSDoc `@throws` 声明矛盾，AI 解析失败被吞掉。
- **修复方向**：改用非贪婪 `\{[\s\S]*?\}` + 括号深度计数定位第一个完整 JSON 对象；找不到时抛 Error 触发 502。

### BUG-005 · coach.js 配额预扣后判断 + 无事务回滚

- **文件**：`backend/src/routes/coach.js:78-89`
- **原严重度**：High · 复核后：High · **confidence**：high
- **类别**：error-handling
- **证据**：`checkAndIncrementUsage` 先 INSERT/UPDATE 后判断，第 21 次请求先 `count=21` 入库再 429；`chatCoach` 抛错时无事务回滚，额度被消耗但用户没拿到回复——与 UI 承诺的 20 次/天不一致。
- **修复方向**：chat 入口先 SELECT count，超限直接 429 不入库；消息存储 + 用量扣减放在 `neon.transaction` 里。

### BUG-007 · auth.js 注册唯一约束冲突未捕获

- **文件**：`backend/src/routes/auth.js:37-43`
- **原严重度**：High · 复核后：High · **confidence**：high
- **类别**：boundary
- **证据**：SELECT-then-INSERT 无事务；`migrations/001_create_users.sql:5` 声明 `email TEXT NOT NULL UNIQUE`，并发同邮箱注册时后到者抛 PG 23505，未被 try/catch 捕获 → 全局 500 handler → 客户端收到 500 INTERNAL 而非 409 EMAIL_TAKEN。
- **修复方向**：包 try/catch 检测 PG 错误码 23505，命中时返回 409 EMAIL_TAKEN。

### BUG-012 · calc.ts bmrHarrisBenedict 缺 NaN/Infinity 校验

- **文件**：`src/core/calc.ts:30-40`
- **原严重度**：High · 复核后：High · **confidence**：high
- **类别**：boundary
- **证据**：`bmrHarrisBenedict` 与 `ageFromBirthYear` 无 `Number.isFinite` 校验；`weightKg/heightCm/birthYear` 为 NaN/Infinity/负数/未定义时返回 NaN，沿 tdee→dailyTargetKcal→UI 显示 "NaN kcal"。
- **修复方向**：入口对入参做 `Number.isFinite + 范围` 检查；NaN 时抛 Error 或返回 0。

## 3. 中等严重 Bug（仅入报告，下个版本再修）

### BUG-001 · friends.js UUID 校验宽松 + 缺 try/catch
- **文件**：`backend/src/routes/friends.js:210-213`
- **复核后**：Medium / error-handling
- **证据**：正则 `/^[0-9a-f-]{36}$/i` 接受 36 个短横线；路由内全部缺 try/catch（grep 在 `friends.js` 全文件无 try/catch/next 包装）。
- **修复方向**：UUID 校验改用 zod `uuid v4`；路由处理器外层包 async try/catch → 503。

### BUG-002 · recognize 路由 `err.message` 泄露上游信息
- **文件**：`backend/src/routes/recognize.js:68-75`（注：finding 误写 index.js:68，实际在 routes/recognize.js）
- **复核后**：Medium / error-handling
- **证据**：catch 里 `message: err?.message` 直回客户端；可能含上游 HTTP 状态码、响应体摘录、env 变量名等侦察信息。注：API key 在 Authorization header 中不通过 err.message 泄露，但其它侦察信息真实。
- **修复方向**：catch 只回 `"识别失败，请稍后再试"`；原始 err 内部 console.error 完整堆栈；统一走 `error()` helper。

### BUG-004 · minimax.js mimetype 无白名单
- **文件**：`backend/src/services/minimax.js:101`
- **复核后**：Medium / bug
- **证据**：`mimetype` 直接来自 `req.file.mimetype`（client-controlled），后续无白名单校验。非图像文件被静默传给 MiniMax 浪费配额，且为 defense-in-depth 缺口（data URL 仅出站，不会反射给客户端，故非 XSS）。
- **修复方向**：入口处白名单 `image/jpeg, image/png, image/webp, image/heic`，否则 throw `'unsupported mime'`。

### BUG-006 · friends.js `blocked` 状态死代码 + 设计缺陷
- **文件**：`backend/src/routes/friends.js:106, 154-169`
- **复核后**：Medium / bug
- **证据**：line 106 检查 `row.status === 'blocked'`，但 `/friends/reject` 只写 `'rejected'`，从未写 `'blocked'`——'blocked' 分支在正常业务流中是死代码；'屏蔽'与'拒绝'两种意图仅用 status 字符串区分。
- **修复方向**：为屏蔽加专门的 `blocked_by_user_id` 列；reject 后可直接删除行；blocked 检查移到 `/friends/request` 之前统一处理。

### BUG-008 · auth.js requireAuth 缺 try/catch
- **文件**：`backend/src/auth.js:54`
- **复核后**：Medium / error-handling
- **证据**：`requireAuth` 中 `await sql` 无 try/catch（仅 `verifyToken` line 45-52 有）；Neon HTTP 在网络抖动 / DB 不可达时抛错冒到 500 handler，前端 client.ts 不识别 AuthError，UI 一直显示"服务器启动中"。
- **修复方向**：SQL 查询外包 try/catch → 503 SERVICE_UNAVAILABLE。

### BUG-009 · exercise 路由 `processingMs` / `source` / `rawText` 丢失
- **文件**：`backend/src/services/minimax.js:336-337` + `backend/src/routes/recognize.js:90-104` + `backend/src/schemas/index.js:31-46` + `src/types/index.ts:118-126` + `src/app/exercise/screenshot.tsx:114-122`
- **复核后**：Medium / integration
- **证据**：exercise 路由只回 `parsed.data`（zod 输出），meal 路由显式回 `processingMs/modelVersion/comment`；后端 zod schema 故意 drop `processingMs/modelVersion`；前端 `ExerciseEntry` 无 `source/rawText` 字段；`recognizeExercise` 实际产生 `source/rawText/processingMs`，"来自 Keep" 标签永远看不到。
- **修复方向**：exercise 路由回 `processingMs/source/rawText`；前端 `ExerciseEntry` 加可选字段并在 UI 展示。

### BUG-013 · useAppStore updateMeal 缺回滚
- **文件**：`src/store/useAppStore.ts:100-110`
- **复核后**：Medium / error-handling
- **证据**：先 `set({ meals: next })` 再 fire-and-forget `repo.saveMeal(changed)`，失败仅 console.error；下次冷启动 hydrate 用旧 DB 数据覆盖用户编辑——静默数据丢失。
- **修复方向**：saveMeal 失败时回滚内存到 `prev`，并 `set({ hydrateError })` 提示用户。

### BUG-015 · meal/add 持久化未压缩 / 临时 uri
- **文件**：`src/app/meal/add.tsx:123, 175`
- **复核后**：Medium / bug
- **证据**：选图后 `setImageUri(asset.uri)` 直接写入 Meal 并持久化；asset.uri 可能是 `content://`（权限过期）或 cache 临时文件（系统清理后失效），几个月后 dashboard 显示裂图。
- **修复方向**：识别成功后用 `expo-file-system` 复制到 `documentDirectory` 持久路径；保留原 uri 仅作缓存展示。

### BUG-016 · setProfile 失败时 UI 显示误导"保存成功"
- **文件**：`src/store/useAppStore.ts:85-90` + `src/app/(tabs)/profile.tsx:112`
- **复核后**：Medium / error-handling
- **证据**：setProfile catch 仅 console.error；profile.tsx line 112 同步触发 `Alert.alert('保存成功')`——保存失败时 UI 误导用户。grep 全 src/ 未发现任何 catch 触发 toast/alert。
- **修复方向**：catch 分支 `set({ hydrateError: '保存资料失败，请重试' })` 或单独 `lastSaveError` 字段。

### BUG-018 · formatTime Invalid Date 显示 'NaN:NaN'
- **文件**：`src/components/FriendSummaryCard.tsx:53-60`
- **复核后**：Medium / boundary
- **证据**：`new Date(invalid)` 返回 Invalid Date 不抛错，`d.getHours()` 返回 NaN，`String(NaN).padStart(2,'0')` 返回 'NaN'；UI 显示 'NaN:NaN'。另一附带问题：UTC ISO 字符串直接 `getHours()` 转本地时区，无 '本地时间' 提示。
- **修复方向**：`Number.isFinite(d.getTime())` 判定有效性，Invalid 时返回 `'未同步'`；UI 标签加 '本地时间'。

### BUG-019 · loadToday 失败不清旧 data
- **文件**：`src/store/useFriendsStore.ts:122` + `src/app/friend/[id].tsx:22-31`
- **复核后**：Medium / error-handling
- **证据**：loadToday catch 返回 null 时，`useFriendDetailScreen` 不清旧 data——用户同时看到旧数字 + 错误提示，UX 不一致。
- **修复方向**：loadToday catch 保留旧缓存（已做），并通过 `useFriendsStore.lastError` 区分 stale vs fresh；或 `FriendToday` 加 `fetchedAt` 字段。

### BUG-020 · recognizeWithImage AbortError 漏 catch
- **文件**：`src/api/client.ts:213-237`
- **复核后**：Medium / bug
- **证据**：仅 try/finally 无 catch，30s `AbortController` 超时后 fetch 抛原生 AbortError 直接外抛，UI 显示 'AbortError' 文案而非'识别超时，请重试'。
- **修复方向**：包 try/catch，AbortError 翻译成 `'识别超时，请重试'`；其他网络错误翻译成 `'网络不可用'`。

## 5. 性能 / 渲染发现（仅入报告，按 spec 不动代码）

### 5.1 启动 / hydrate（核心瓶颈）

- **PERF-002 · `_layout.tsx` 全屏 loading 阻塞首屏（High）**：!authHydrated 时不透明 loading View 覆盖整个 Stack；/auth/me 网络往返 10-30s（Render free 冷启动）期间 UI 不可见。**建议**：loading 蒙层改为只覆盖 (auth) 路由组；cached user 渲染主屏；/auth/me 5s 超时 → status='offline' 放行。
