# FitLens v0.5 — 好友动态版 产品概述

> 状态：设计稿 v0.1
> 作者：产品/系统设计
> 最后更新：2026-07-02

---

## 1. 一句话定位

**FitLens 是一款本地优先的减脂热量记录 App，v0.5 起新增"小范围好友"模块，让同班同住的熟人能看见彼此"今日总摄入 / 总消耗"两个数字，互相打气但绝不暴露吃了什么、体重或 BMI。**

---

## 2. 范围

### 2.1 在做什么（v0.5 范围内）

- **账号系统**：邮箱 + 密码 + JWT，本地数据继续存 SQLite，登录后**增量同步**到云端。
- **好友关系**：手动搜索对方邮箱发送请求 → 对方接受 → 建立**单向授权**的好友关系。
- **好友可见数据**：仅"今日摄入 kcal"与"今日消耗 kcal"两个聚合数字 + 一个昵称/头像。
- **今日动态**：好友主页里只看到这两个数字 + 一个一行鼓励按钮（点赞/加油），看不到任何明细。
- **个人主页**：用户自己的二维码（扫码加好友）和我的好友列表。
- **隐私优先**：服务端 API 拒绝返回任何 < 今日聚合级 的字段；前端 store 不缓存好友的明细。

### 2.2 不做什么（明确边界）

| 不做 | 原因 |
|---|---|
| 不做推荐好友 / 通讯录匹配 / 附近的人 | 用户只要小范围同学同事，避免社交压力 |
| 不做动态 feed / 朋友圈时间线 | 只看"今日两个数字"，不是内容社区 |
| 不做群组 / 班级 / 减脂挑战 | 单向好友 + 静态数字已经够用 |
| 不暴露食物明细、餐次、卡路里分布 | 体重/饮食羞耻，敏感 |
| 不暴露体重、BMI、身高 | 同上 |
| 不做排行榜（摄入最少 / 消耗最多） | 会让"饿肚子"成为隐性竞争 |
| 不做聊天 / 评论 / @ 提醒 | 噪音太大；鼓励用按钮代替 |
| 不做账号注销页面（v0.5） | 范围外，预留接口 |
| 不做密码重置邮件流（v0.5） | v0.5 先内置"联系开发者重置"，v0.6 加邮件 |
| 不做图片/头像云端存储 | 只用昵称首字母 + 颜色块作默认头像 |
| 不做推送通知（v0.5） | 进入 App 内才看今日动态 |

## 3. 用户故事（5 条）

### US-1 注册与登录
> 作为一名新用户，我想用邮箱 + 密码注册一个账号，这样我的数据能跨设备同步，而我已经记在手机上的本地数据不会丢失。

**验收**：注册成功后，本地 SQLite 中的所有 meal/exercise/diary **保留不变**；下次启动自动上传增量；登出后本地数据仍在，但不再上传。

### US-2 加好友
> 作为阳，我想通过搜索室友小张的邮箱向他发送好友请求，对方点接受后，我们就是好友了。

**验收**：搜索邮箱命中已注册用户 → 显示昵称 + 邮箱 → 点击发送请求 → 对方收到"待处理"列表 → 接受后双方好友列表都显示对方。

### US-3 看好友今日数字
> 作为阳，我想点开好友小张的主页，看到他今天"摄入 1450 kcal / 消耗 320 kcal"，并可以给他点个赞。

**验收**：好友详情页只有两个数字 + 昵称 + 头像 + 点赞按钮；任何明细 API 调用都被服务端拒绝（403）。

### US-4 隐私保护
> 作为一名在意隐私的用户，我想确认我的体重、吃了什么、BMI 不会被好友看到，只能看到两个聚合数字。

**验收**：抓包检查 `/friends/:id/today` 返回的 JSON 字段，只有 `{nickname, avatarSeed, intakeKcal, burnedKcal, targetKcal?}`，无任何 food/exercise 详情。

### US-5 离线使用
> 作为一名经常在操场没信号的减脂用户，我想断网时也能记餐记运动，连上网后数据自动上传。

**验收**：飞行模式下添加一餐 → 数据写入本地 SQLite → 联网后 5 秒内该餐出现在云端；好友那边能在我上传后看到数字更新。

## 4. 用户画像（隐含）

- **阳**：大二学生，飞行器专业，170cm/65kg，目标温和减脂。
- **同班同住的 3-5 个室友 / 同学**：也用 FitLens，互相看数字互相打气。
- 总规模 < 50 人；不是社交产品，是工具 + 熟人激励。

---

## 5. 与现有 v0.4 的关系

| 模块 | v0.4 | v0.5 |
|---|---|---|
| 本地 SQLite（meals/exercises/diaries/profile） | 主存储 | 主存储（不变） |
| AI 识别（MiniMax 后端） | 在线 | 在线（不变） |
| 7 日趋势 | 本地计算 | 本地计算（不变） |
| 账号 / 好友 | 无 | **新增** |
| 数据同步 | 无 | 登录后增量同步（增量、不覆盖） |

**关键原则：v0.5 必须在 v0.4 完全离线可用这个特性上"叠加"云能力，绝不能破坏离线体验。**
